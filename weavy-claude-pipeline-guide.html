node 04

Identity-lock: три ошибки, которые ломают сходство

Все три обнаруживаются на одном и том же кейсе: персонаж генерируется похожим на сборную «смесь» из референсов, а не на конкретного человека.

ошибка · батч в одном нодеВсе референсные фото загружены пачкой в один input-image. Модель использует только одно фото из пачки — то, что выбрано по умолчанию, остальные игнорируются.
фиксКаждое фото — отдельный нод: image 1, image 2, image 3… В промте текстом описать, что брать с какого: «крупный план — image 1, анфас — image 2, ¾ — image 3».
ошибка · разнородные референсыФото сделаны в разном свете, на разную оптику, с разным фоном. Тени и геометрия лица плывут между кадрами — модель не может закрепить форму.
фиксОдна съёмочная сессия, один нейтральный фон (белый/зелёный), один источник света. Развороты: анфас + ¾ влево + ¾ вправо + профиль при возможности — лицо несимметрично, нужны обе стороны. Снимать на портретный/телефото объектив, не на широкий угол (GoPro и подобная оптика сжимает пропорции и искажает черты).
ошибка · костюм тянет за собой чужую внешностьПри похожем типаже модель смешивает лицо референса одежды с лицом героя — получается «дочь» или «сестра» персонажа, а не он сам.
фиксВырезать костюм отдельно, без человека, на нейтральном/зелёном фоне → отдельный нод → добавлять в генерацию как ингредиент одежды, а не как референс внешности. Альтернатива: character sheet героя в нейтральной одежде с нескольких ракурсов + отдельный нод с костюмом, который накладывается уже в финальной сцене.
«У нас лица несимметричные — рабочая сторона не любая. Поэтому делай развороты на обе стороны, а не просто анфас.»

настройки

Технические параметры нодов

вес файла

Входные фото ≤ 2 МБ

Файлы по 10 МБ перегружают граф и заметно тормозят генерацию. Экспортировать референсы с более низким качеством — для крупного плана 2 МБ достаточно.

формат вывода

2K, 16:9 вместо auto

Цена одинаковая что для базового разрешения, что для 2K — качество в этом случае примерно вдвое выше при той же стоимости. Ставить 2K по умолчанию.

роутер

Размножение через Router-нод

Чтобы один и тот же элемент (например, итоговый character sheet) подавать одновременно в несколько следующих нодов — между ними ставится router, а не дублируется загрузка фото вручную.

claude · skills

Skill vs Project — разделение контекста

Skill — это навык, переиспользуется в любом количестве проектов (как «умею пилить дерево» — применимо и к стройке дома, и к скворечнику). Project — контекст конкретного фильма: сценарий, паспорт сцены, гонорары. Один и тот же skill подключается в разных проектах, проекты друг с другом не пересекаются.

  1. Установка скилла. Settings → Customize → Skills → справа кнопка + → Create / Upload skill → выбрать скачанный файл скилла. Включить тумблер активности справа от названия.
  2. Вызов в чате. Набрать символ / → внизу появится список подключённых скиллов → выбрать нужный → Enter.
  3. Порядок скиллов в этом конвейере: weavy-nano-banana-node-prompts (промты для нодов) → storyboard (раскадровка) → filmcheck (паспорт сценария) → shotlister (покадровая разбивка) → cinemadirector (финальный видеопромт).
  4. Не редактировать уже отправленное сообщение для вызова скилла повторно — это иногда блокирует ввод. Писать новое сообщение.
node 02

Сценарий ≠ раскадровка

Литературный сценарий описывает «что происходит». Раскадровка — это разбивка на конкретные планы с киноязыком, готовая к генерации кадр за кадром.

Запрос модели

Явно просить: «распиши storyboard» — модель раскладывает сцену на общий план → средний план → крупный план, с маркировкой WS / MS / CU и т.д., в порядке, уже выстроенном под монтаж.

Плотность кадров

На 30 секунд ролика — минимум 10–12 кадров, не 5. Меньшее количество означает резкие, «грубые» склейки без промежуточных планов.

node 03

Filmcheck — паспорт сценария

Стартовый пакет перед началом любых генераций: полная инвентаризация фильма, выполненная автоматически вместо ручного разбора по сценам.

  1. Сценарий грузится в чат целиком, одним текстовым блоком — формат .md, не PDF (экономия токенов и кредитов).
  2. Вызов: /filmcheck → указать язык вывода → выбрать режим: полный отчёт или только тоталы.
  3. На выходе — документ с разбивкой по сценам: герои, реквизит, локации, костюмы, нужные ракурсы. То, что раньше собиралось вручную.
  4. Формат вывода — markdown-документ, не PDF: компактнее, меньше токенов на дальнейшую обработку.
claude · project

Сборка проекта под конкретный ролик

  1. New Project → название по ролику (например tomi_01) → краткое описание обязательно.
  2. В Knowledge загрузить: полный текст сценария + готовый файл filmcheck.
  3. Project Instructions для этого случая не обязательны — модель уже опирается на файлы Knowledge.
  4. Скиллы (filmcheck, cinemadirector, shotlister) подключаются в любом проекте — они не привязаны к конкретному фильму.
ошибкаСценарий разбит на отдельные подписи «Сцена 1 / Сцена 2 / Сцена 3» при загрузке. Модель путает текстовые метки со сценами фильма и не достраивает кадры между ними.
фиксГрузить сценарий цельным текстом, без собственной разметки на сцены — разбивку по сценам делает сам скилл (filmcheck / storyboard), а не пользователь вручную.
node 05

CinemaDirector — финальный видеопромт

Когда в проекте уже лежит сценарий и filmcheck, скилл собирает таймлайн-промт под Seedance 2.0 (формат, совместимый с генерацией внутри Higgsfield) по запросу «распиши сцену N».

Зависимость от предыдущих шагов

Качество промта на этом шаге напрямую зависит от того, насколько точно прошёл этап filmcheck — реквизит, ракурсы и состояние героя по сценам берутся именно оттуда, а не придумываются заново.
